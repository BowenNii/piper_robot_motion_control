## 2. 最终ABC实验设计

三组均使用本轮的MOVE J接口，区别在于目标发送方式：

| 条件 | A：单次目标 | B：重复终点 | C：自定义位置序列 |
| --- | --- | --- | --- |
| 发送内容 | 一次最终关节角 | 重复同一最终关节角 | 随五次时间缩放变化的关节角 |
| 发送数量 | 1次 | 539次 | 539次 |
| 发布频率 | 单次 | 50Hz | 50Hz |
| 已知中间时间参考 | 无，固件内部轨迹未记录 | 无，固件内部轨迹未记录 | 有，上位机发布序列已记录 |

六轴目标约为 `[0.3, 0.3, -0.3, 0.3, 0.3, 0.5] rad`，返程返回零位，每段采用实测起点。34段包含重复轮次，保留完整记录，主图选择见 `inventory.json`。

`speed_percent=5`不是5°/s。A/B约3.36s完成最大0.5rad行程，C的指令窗口约10.76s；三组并未匹配实际速度与加速度，因此不能把差异全部归因于发送机制，也没有充分证据确认抖动根因。

## 3. 最终验证结果

以下数值来自保留的收尾数据及其Python/MATLAB一致性核查。末端均指**反馈关节角经模型回算的link6坐标系**，不是外部测量的夹爪TCP。

| 指标 | 六轴C去程 | 六轴C返程 |
| --- | ---: | ---: |
| 反馈位置到参考三维折线最大距离 | 0.467mm | 0.436mm |
| 参考位置到反馈三维折线最大距离 | 0.151mm | 0.200mm |
| 原始时间轴位置误差峰值 | 0.926mm | 1.001mm |
| 原始时间轴位置误差RMS | 0.416mm | 0.384mm |
| 原始时间轴最大关节绝对误差 | 0.334° | 0.294° |
| 原始时间轴姿态误差峰值 | 0.565° | 0.494° |
| 固定46ms对齐后的位置误差RMS | 0.251mm | 0.271mm |

34段记录均执行成功，已记录状态未出现故障行；稳定末段最大关节反馈偏差约0.071°。六轴A/B的J6达到99%行程晚于其他轴，不代表J6等其他轴结束后才启动。

主要结论：

- **空间路径与实时跟踪应分别评价。** 经过相近的路线，不代表相同时刻达到相同位姿；A/B没有已知中间参考，不能把偏离C路径判为跟踪失败。
- **系统存在可观察的整体滞后。** 六轴46ms仅由C去程中段估计，原样用于返程；对齐后误差减小但不为零。这不是独立测得的CAN延迟，也不是已实现在线补偿。
- **目标到位与自定义位置序列执行链路已跑通。** 但没有证明固件严格执行了上位机规划的速度、加速度，也没有证明未来任务精度合格。

## 4. 数据质量与结论修正

旧解码器可能把上一轮尾帧与下一轮起帧拼接，导致5段旧统计持续超过2ms。正式分析按本设备日志的 `0x2A2 → … → 0x2A7` 顺序重新组帧，原始日志未修改。

- 重新解码34段，共114188个完整组；最大六帧接收跨度1.335ms，完整组中超过2ms的比例均为0。
- 共过滤24个起始未对齐帧；不完整组和丢弃情况另存诊断，不能只看成功组的最大值。
- PC最大发布前迟到2.561ms，最大ROS反馈接收间隔8.888ms。它们不能证明CAN、固件与电机执行具有硬实时保证。

因此，旧的跨轮拼帧跨度不再作为真实通信异常或抖动原因的证据。接收跨度小也不等于六个关节与位姿严格同时采样。

## 5. 误差定义与完成边界

| 指标 | 比较对象 | 能说明什么 |
| --- | --- | --- |
| FK一致性误差 | 自建FK位姿与厂家CAN反馈位姿 | 模型与解码约定的一致性 |
| 空间路径误差 | 反馈回算位置与参考三维折线 | 路线接近程度，不保证姿态、顺序或时序 |
| 原始跟踪误差 | 反馈与实际发布时间构造的零阶保持目标 | 未补偿系统的逐时刻跟随表现 |
| 延迟对齐误差 | 使用固定时间平移后的反馈/参考比较 | 分析滞后影响，不能替代原始实时指标 |

当前验收配置中的关节、位置、姿态容差未预先设定，相关超限指标为NaN表示“未设定”，不是零超限。实验统计值不能反过来直接充当验收标准。

**项目1完成的是运动学、执行和分析链路验证。** 尚未完成外部绝对精度测量、夹爪TCP标定、抓取成功率验证、全工作区/负载验证或硬实时认证。轻微抖动保留为观察项；若增大、报警或妨碍任务，再专项排查，不作为本阶段无限延长的收尾条件。
